# caddy — service backend + tool surface

Pure-Rust plugin (**no bash/compose/provision scripts**) that drives an
already-running Caddy instance over its **admin API** (default `:2019`). The
HTTP client rides orca's `http.request` capability (`delegated-http`), so the
plugin links no reqwest/rustls. Optional bearer-token auth (the admin API is
unauthenticated on localhost by default).

One binary registers **two facets** on the `Plugin` builder: a `ServiceBackend`
(the generic `service.*` lifecycle) and the `caddy.*` `#[orca_tool]` surface.

## Tools
- [x] `caddy.{list,detail,create,update,delete}` — endpoint-registry CRUD
      (generated by `#[endpoint_resource]`; `routes` fallback list + optional
      `#[secret]` `api_key` in the abstract secrets domain)
- [x] `caddy.status` — reachability + server/route/upstream counts
      (`GET /config/` + `GET /reverse_proxy/upstreams`; Caddy exposes no version endpoint)
- [x] `caddy.config.get` — the full current config JSON (`GET /config/`)
- [x] `caddy.route.list` — enumerate reverse-proxy routes (host → upstream) across all http servers
- [x] `caddy.route.set` — idempotent upsert: point a host at one or more upstreams
- [x] `caddy.route.delete` — remove the reverse-proxy route(s) matching a host
- [x] `caddy.reload` — re-apply the running config (`POST /load`)

### Route model — surgical `/config/...` edits, not full `/load`
Caddy has no "upsert route by host" primitive and applies every admin write
live. `route.set`/`route.delete` read the full config once (`GET /config/`),
mutate only the target server's `routes` array in memory (least-destructive: an
existing host has its `reverse_proxy` upstreams replaced in place; a new host is
appended as a canonical route), then write just that subtree back with
`PATCH /config/apps/http/servers/<server>/routes`. This leaves TLS automation and
every other app untouched. `caddy.reload` is the one deliberate full re-apply —
it reads the running config and `POST /load`s it straight back
(`Cache-Control: must-revalidate`), a safe no-op refresh (Caddy has no dedicated
reload verb).

## Service backend (`service.*`)
- [x] declares runtimes (docker/podman/lxc/vm), capabilities
      (deploy/backup/restore/configure/status), default port, and `data_paths`
      (`/config`, `/data`) for the generic pluggable backup
- [ ] `workload_spec` / `configure` / `status` — planned (currently
      `ServiceError::unimplemented`)

## Provided generically by orca (NO code here)
- endpoint reachability resolution (`route::resolve_reachable` over the `routes` list)
- secret storage/resolution (`caddy.<endpoint>.api_key`)
- the CLI / REST / MCP surfaces over every `caddy.*` tool
